# 每次请求的有界工作上下文

范围：在既有官方 Qloo / pi 运行时内，限制每次交给模型的工作视图；项目记录、完整原始返回、提案校验、批准规则及 HTTP（应用程序接口请求）账本保持权威。没有新增依赖、摘要模型、向量库、界面或实体确认流程。

## 原因与固定预算

本地仍使用 `contextWindow=32000`、`maxTokens=12000` 和安全余量 `4096`。这三个值没有增加。预算条件为：完整请求的离线输入估算 + 12000 + 4096 ≤ 32000。它是本地配置，并非服务商模型能力上限的声明。

截至本次官方文档核对，`deepseek-flash` 对应 V4.1 Flash 1017，文档列出 1M 上下文、最多 384K（393216）输出，且思考模式默认启用。本地 32000 / 12000 及 SDK 的 `reasoning:false` 既不定义该模型的能力，也不保证服务商思考模式关闭；本任务不改变这些模型配置或初始研究的既有行为。

旧逻辑使用 SDK（软件开发工具包）估算器：有可用的最新 assistant（模型回复）usage（用量）时，采用该回复的总用量加后续消息估算；总用量已包括输入、输出及缓存，推理用量属于输出的子集，不能再相加。该路径不会重新加此前前缀或完整工具定义。重建工作前缀后，旧 usage 不再代表新前缀，因此仅将发送副本的 usage 清零，历史原件保持原样。

新估算把 ASCII（基本拉丁字符）按四字符一个词元、其他字符按一个词元计数，明确标为 `offline-serialized-ascii4-other1`，不是官方分词器或实际用量。请求前先估算真实模型内容、系统指令及当前工具定义，排除不会发送的 `details`、时间戳和历史 usage；不足时收起当前 Qloo 字段展开。随后在公开 `onPayload` 钩子中，等待原钩子完成，再对最终序列化请求及全部包装字段计数。仍不足或输出容量被降低时，本地停止，报告组成计数、最大组成与超出量；不缩成一个词元输出，也不重试恢复。

## 工作视图与完整证据

- 每次模型请求重新构建一个当前工作消息，保留完整需求、必须项、禁止项、版本、已确认概念、锁定字段、当前待审稿、反馈、未知项及资源余额。不会用文本截断这些约束。
- 证据默认提供卡片查询背景、实际输入引用、必要工作流上下文、实体身份与字段目录。过大的历史查询只显示明确标记的预览与本地读取路径；精确查询仍保存在权威证据卡中，当前需求与硬性约束保持完整。每页最多 12 个实体，给出总数与下一页位置；完整返回继续保存在权威证据卡中。
- 当前工具回合最多保留 12 个实体；大实体只对前六个展开常用描述与数值字段，本身不超过 1200 个序列化字符的小实体可完整返回。大字段只给明确的 `exact:false` 预览；不能把预览当成精确引用。元数据中的数组、字段数、深度与长文本也受限，省略有标记。
- 一个只读的 `read_project_evidence` 工具绑定当前项目。只给证据卡编号时读取有界实体目录；同时给实体编号和实体相对字段路径时读取精确 JSON（结构化数据）值。不提供实体编号时，字段仅允许 `query` 或 `query.*`，用于读取该证据卡的原始查询及其中的叶子值，可使用数字数组下标。不能读取任意卡片或项目字段；缺少实体字段路径、跨项目、原型键、URL（网址）及文件路径均不能读取。字段超过 6000 个序列化字符时返回 `too_large` 和预览，不冒充完整值。不发生外部请求或状态写入。
- Qloo 先写入完整原始返回，再生成模型视图；工具结果的完整 `details` 继续保存在官方会话记录。模型只读取有界的 `content.text`。`needs_input` 的历史歧义保存为有出处的未确认观察；后来的查询成功不会被视作用户确认。
- 未确认观察从当前消息及当前项目既有会话中导出，跨用户提交和运行时重启保留；工作视图最多展示最近 12 项，并给出省略数。关闭的会话通过公开的纯解析函数读取，不调用可能迁移并重写文件的 `SessionManager.open`。当前用户提交仍可另建会话，旧文件不改写。
- 历史只保留最近一个完整工具回合，整个 assistant 工具调用和对应结果成组保留。缺少同批结果、重复或孤立结果会本地停止。历史证据由当前权威索引和按需字段读取承接，不把旧工具原文全部重放。
- DeepSeek 思考模式要求保留的工具协议回合携带对应 `reasoning_content`；当前保留回合的内容仅作为不透明协议数据保留并自动计数，不提取、解释或展示私有推理。旧回合整体移出工作视图。既有局部修改的思考模式设置保持不变。

现有套件没有本任务可直接使用的、名为 `transformToolResult` 的配置钩子或统一的请求预算配置入口，因此复用公开 Agent 工具结果钩子与模型请求钩子；没有访问私有 SDK 字段或重写调用循环。

## 同一失败记录的离线对照

同一份停止记录的九条安全消息及完整证据，在隔离副本中通过真实运行时钩子回放。没有读取原始私有推理正文；因此不能据此证明真实服务商的思考协议或创意质量。旧记录及账本未重新启动或重置，25 个原始文件哈希保持一致。

旧 SDK 路径复现输入估算 16865，只剩 11039 个输出词元；`16865 + 12000 + 4096 = 32961 > 32000`，在发送前停止。下表使用同一种新序列化估算进行对照，不能与旧 SDK 数字混作同一种测量。

| 组成 | 旧请求估算 | 新请求估算 |
| --- | ---: | ---: |
| 系统指令 | 1224 | 1214 |
| 工具定义 | 1535 | 1854 |
| 当前任务状态，含证据索引 | 680 | 6464 |
| 工具证据返回 | 12552 | 2901 |
| 模型历史消息 | 487 | 264 |
| 完整序列化请求 | 16507 | 12725 |

各行独立估算，四舍五入和包装分隔符不同，不能逐行相加代替完整请求。新路径 `12725 + 12000 + 4096 = 28821`，到达一次模拟发送边界，实际 `max_tokens=12000`；正式内容及原始证据保持一致。本轮真实 DeepSeek 和 Qloo 请求均为零。这不证明真实服务商接受、部署成功或提案质量。

完整离线回归 119/119 通过。直接相关测试覆盖：连续工具回合、同批并行调用配对、旧用量不污染新前缀、单次一万实体及超大字段、查询与元数据返回、精确字段读取及拒绝、歧义跨提交及重启、最终钩子追加大字段、不可压缩约束停止，以及经过实际提案执行器的引用纠正。模拟真实传输的每次发送均检查完整预算与 12000 输出容量。
