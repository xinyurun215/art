# Vercel 受保护预览

此适配复用现有页面、请求路由和官方 Qloo Harness（运行套件），无需切换框架。接受 `VERCEL_ENV=preview` 或 `production`。生产环境的评审域名 `art-lovat-two.vercel.app` 免基本身份验证，项目按浏览器访客 Cookie 隔离，其他浏览器读取同一项目链接会得到 404；其他域名仍需基本身份验证。以下准备步骤最初为预览环境编写。

1. 确认目标 art Vercel 项目（与旧 TasteTrip 项目隔离），无需重复创建。仅在用户具体批准的隔离测试 Postgres（关系数据库）中，由数据库管理工具执行一次 `migrations/001-postgres.sql`；Neon 可使用 pooled（连接池）TLS 连接地址。应用不会自动执行迁移或导入本机历史项目。
2. 仅在目标项目 Preview（预览）环境配置 `DATABASE_URL`、独立随机 `ART_PREVIEW_ACCESS_KEY`（预览访问密钥）和 `ART_ENABLE_LIVE=false`；`VERCEL_ENV` 由 Vercel 提供。`.env.vercel.example` 仅作为字段参考；本轮离线验收无需填写或搬迁模型、Qloo 密钥，不导入本机 `.env`。
3. 核实现有 Hobby Standard Protection（标准保护）对 Preview 的覆盖，以及正式域名不受其保护（包括正式 vercel.app 域名）的边界；不要自动更改安全设置或切换为 All Deployments（所有部署）。应用另以浏览器原生 Basic Authentication（基本身份验证）保护首页和全部 API（应用程序接口）：用户名为 `preview`，密码是预览访问密钥。未设置密钥、数据库或预览环境时直接拒绝访问。静态脚本和样式不含项目或秘密。不要公开分享访问密钥；这不是多人账号或项目权限系统。
4. 保持 Node.js（运行环境）22.19+，核对平台的 Node 版本。`vercel.json` 把首页与 `/api/*` 接到同一 Node Function（函数）；函数最长 300 秒，应用在 250 秒中断并保存状态。平台设置、真实函数打包与部署行为需单独验证。

项目、证据、待审稿、版本、运行记录和 HTTP（网络）请求账本保存在数据库。函数请求等待本轮结束才响应，不在返回 202 后依赖内存队列。执行许可按项目持有：同一项目同时只有一个运行，竞争请求返回 409，未排队；不同项目可在不同函数实例上并行。同一函数进程内仍串行执行，同时落到同一实例的请求返回 409。每轮用官方公开 `SessionManager.inMemory`（内存会话）接收权威项目视图，不复制或重放历史私有会话文件；临时文件仅供官方 SDK（开发套件）设置使用。

项目存储版本采用 compare-and-swap（比较后更新），避免并发静默覆盖。每个真实 HTTP 尝试前，事务同时提交共享额度和 `reserved_unknown`（已预留、结果未知）请求记录；失败或提交结果不确定时禁止外发、不自动重试、不退款。每项目额度 `ART_MODEL_HTTP_LIMIT`、`ART_QLOO_HTTP_LIMIT`（默认 6/6）与部署合计用量跨函数实例累计，不随冷启动重置。部署合计上限只在设置 `ART_SHARED_MODEL_HTTP_LIMIT`、`ART_SHARED_QLOO_HTTP_LIMIT` 时生效，未设置则不限。修改这些配置会在下一次数据库操作时生效，已记录用量保留、不重置。数据库失败不会回退到内存或 `/tmp`。

250 秒主动中断会标记 `interrupted`（已中断）。平台强制终止时，已预留的请求可能已经发出；在执行许可（lease，租约）过期后的下一次读取会将未完成运行标为中断。请求响应的独立账本保留已确认结果，无法确认的预留仍标为未知；不会把中断写成完成，也不自动重复供应商请求。恢复只还原已保存正式内容、待审稿、证据和账本；停止只作用于出问题的项目，不影响其他项目：模型或存储故障会停止该项目后续的真实请求，需要新建项目；已中断的项目由用户明确重新提交时可以继续，系统不会自动重发。本适配不提供用量重置或退款入口。Qloo 业务失败或额度耗尽只停止该项目的文化查询，预算内模型仍可收尾。无法保证供应商在取消后停止处理已接收请求。

本轮离线测试不等于真实模型/Qloo 验证、浏览器基本身份验证交互验收或真实 Vercel 部署成功。没有 `.vercel/project.json` 时，官方 `vercel build`（构建）可能要求项目设置；不要自动登录、读取远端环境或上传本机秘密来绕过。

首次创建项目会等本轮处理结束后才将项目标识返回浏览器。如果首次响应前被硬中断，数据库可能已有项目和预留账本，但浏览器尚不知道标识；需由数据库管理侧先核对原记录，不要直接重新创建以免重复已发出的请求。浏览器已有项目标识时可继续读取已保存状态。
